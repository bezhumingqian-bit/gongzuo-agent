# 共作

面向企业团队的桌面 Agent。员工用一句话发起工作，Agent 结合当前空间的目标、资料、适用记忆和授权范围继续执行。个人过程默认私有，已确认的进展与成果按空间规则共享；内部小应用发布仍是后续规划。

## 项目状态（2026-10-16）

**暂停迭代，保留当前源码快照，不代表生产发布。** 暂不推进新功能、正式部署或团队协作服务。现有资料、测试和已安装的本地预览版保留；以下“下一阶段”仅是历史规划，不是进行中的排期。

本次收尾包含：真实工作目标的派生标题、按时间／按项目查看同一记录、问候／能力咨询／联调／未使用示例的次级保留、连接状态自动呈现与异常重连、菜单互斥收起、云端成果回收与恢复、静态 PPTX 预览、受限共作内核及 WorkBuddy HTTPS 授权中转代码。没有把本机用户数据、密钥、备份或安装包纳入源码。正式 HTTPS 部署、平台授权及 Apple Developer ID 公证仍未完成。

当前仓库包含一个可运行的 **macOS MVP**。它具备桌面窗口、本地数据持久化和受限的主进程接口。企业微信智能机器人通过 WebSocket 长连接接收消息，也可向企微允许的会话发送工作消息；需要同步可见成员目录时可另外配置自建应用。飞书、普通微信和邮件尚未接入。

## 共作 Agent（B 路径）

共作负责工作界面、适用记忆、成果与执行记录，CodeBuddy CloudAgent 负责云端执行。模式标识仍为 `cloudagent`；没有改用其他后台、申请新额度或覆盖用户已有默认 Agent。

- 在输入框的执行 Agent 列表中直接选择用于新工作／当前工作的执行者；选中后收起，仅当前 Agent 保留二级配置入口。默认执行者仍在设置中保存。新工作保留个人空间默认与「只用本机执行」限制。
- 右侧「成果」显示当前工作的真实回传文件；HTML/图片/PDF/TXT/MD/CSV 可预览，PPTX 提供有范围限制的静态页面预览，Word/Excel/PPT 等文件可在本机打开。PPTX 不等同于 Office 的完整渲染。HTML 须自包含；相关资源文件不会自动被打包为网站。
- HTML 默认静态预览、不执行脚本；开启交互前需确认信任。隔离禁止访问父页面、IPC、外部资源请求与表单，不等于对所有脚本出网通道提供强隔离。离开／切换文件后不沿用交互授权；在本机浏览器打开 HTML 再次提示风险。
- 「执行过程」仅显示引擎返回的工具状态与可靠耗时，每轮最多保留最近 120 步；历史回放缺少时间时不编造。步骤保留在本轮回复中，不自动同步为团队进展；不记录参数、输出或思考正文。
- CloudAgent 发出的命令／删除等权限请求进入工作页的一次性确认；未确认、超时或上游缺少一次性允许选项时拒绝，不回退为永久授权。平台可能不为所有命令发起确认，不能把此界面当作完整沙箱安全保证。空间资料仍由用户明确引用正文，不自动将全库上传沙箱，不新增计费资源。
- 验证：`npm run check`、`npm test`。可选 `scripts/verify-b-path.cjs` 使用临时文件及模拟引擎回复执行浏览器回归；运行环境另需提供 Puppeteer（非桌面运行依赖），脚本会关闭测试浏览器，只可连接专用测试实例。浏览器截图不代表已跑新的真实云端任务。

## 已实现

- macOS 原生窗口与菜单，界面采用 Agent 对话作为主操作区
- 工作主页可切换模块工作台、简洁概览与原 Agent 输入界面；模块可显示、隐藏、排序，布局保存在当前设备
- 精简导航：新工作、我的工作、工作空间、团队小应用；桌面未发布应用时显示空态，不把浏览器示例应用当成已发布成果
- 新建工作、追加消息，并在个人、团队和项目空间之间选择工作归属；公共空间仅提供规范、模板和口径，不允许发起工作
- 工作对话支持输入 @ 或点击“@ 同事”选择当前空间成员；消息保留提及对象和送达状态
- 工作中的单条文字可手动发送给指定企微 UserID；@ 已关联的团队或项目成员时，会向对应 UserID 定向发送提醒并记录每人的结果；任务信息里可指派负责人并通知企微。已连接机器人时优先通过长连接发送，自建应用可作为备用发送方式
- 企微机器人支持“新建 空间名：目标”“更新 工作ID：进展”“查看 工作ID”，按 UserID 校验空间权限、排除重复事件，并将 Agent 回复私聊发给发起者
- 设置中的“工作规则”可按企微发送者、消息前缀和目标空间筛选摘要，交给 WorkBuddy 或内置 Agent 形成待确认的工作；规则默认关闭。窗口右上角“消息收件”可直接查看企微机器人单聊正文，本机最多保留最近 50 条。在工作中明确询问企微来信内容时，最近至多 10 条会临时提供给当前 Agent 回答，不必先逐条引用；需要把特定来信长期放入工作时再选“作为工作材料引用”。旧版本只保存了时间和发送者，无法恢复正文
- 企微通讯录同步只保存应用可见成员的 UserID 与显示名；可将其关联到团队或项目空间，赋予机器人只读或协作权限并撤销
- “我的工作”显式支持按时间／按项目查看同一记录，不复制对话；标题从用户实际目标派生显示，不重写原始目标或权限，不从助手自称推断完成。问候、能力咨询、联调和未使用旧示例保留在次级入口，不计入正式工作
- 从“工作空间 → 新建项目”创建项目空间、关联团队、查看项目工作；创建者可添加待邀请成员，并在“只读 / 协作”之间调整其预设权限
- 工作空间右侧展示该空间的实际资料；可上传文档、按分类和标签整理、搜索、打开、移出及恢复
- 发起工作或继续对话时可主动引用当前空间最多 3 份 PDF、Word 或文本资料；只提取文字，每份最多发送前 12000 字。扫描版 PDF 暂无 OCR，表格和演示文稿尚不能作为 Agent 正文引用
- 输入框旁可将文件上传到当前空间资料，并直接切换新工作的空间；通知、成员和任务更多操作有明确入口
- 对话输入框将执行 Agent 与“工具与技能”分开；Codex 和 Kimi Code 可通过本机已登录 CLI 续接同一工作的文本会话；CodeBuddy 可尝试返回文本；WorkBuddy 默认走本机连接：工作排队，WorkBuddy 通过「gongzuo」MCP 连接器领取、处理并写回（见[连接与测试范围](docs/CONNECTIONS.md#workbuddy-本机连接默认)），开放平台 OAuth 为可选通道；技能示例与企业系统 MCP 尚未接通
- 侧栏搜索可查找本机工作、空间资料和演示应用；团队应用预览可切换页面并录入临时演示反馈
- 工作数据保存到 macOS 用户数据目录，重启后继续使用
- 个人记忆与团队记忆分别保存；可从任务提炼草稿、确认保存、分类打标签并移出记忆
- 设置分为“模型”“Agent”“连接器”三个独立页面；连接状态在界面自动显示，断开时提供重连，配置字段与授权操作二级展开。自动状态检查不发送任务、不调用模型生成、不自动授权；无法安全确认在线时明确标为就绪。企业微信机器人、自建应用和成员目录按需配置
- OpenAI、Kimi 和 DeepSeek 模型均可打开各自开放平台，保存独立的模型 ID 与 API Key 后由内置 Agent 调用；网页或客户端登录不会自动授权 API 调用
- 配置模型、Codex、Kimi Code、CodeBuddy、WorkBuddy 或自定义 Agent 后，Mac 版在新建工作与继续对话时会发起请求，并把响应或安全的错误信息留在工作中；工作会先落盘，Agent 在后台按消息顺序处理，失败或中断可重试；每项工作可单独切换执行 Agent；WorkBuddy 需要有效的 OAuth 访问令牌，自定义 Agent 需实现[共作桥接协议](docs/CONNECTIONS.md)
- 输入框只提供“交给 Agent”，不再提供直接发消息按钮；@ 成员会按工作权限定向提醒。已有工作消息的转发是独立确认动作，不会重发给 Agent
- 模型密钥、外部 Agent 令牌、企业微信应用和机器人密钥由 macOS 安全存储加密后保存；界面只能看到是否已配置
- 团队应用的预览、发布演示和再次改进入口
- 渠道消息的基础策略：归档、低风险自动更新、高影响变更待确认
- Electron 安全边界：上下文隔离、渲染进程无 Node 权限、窄 IPC 接口、禁止任意导航
- Agent 服务抽象；没有模型凭据时使用本地模式

“配置已保存”不等于“连接已验证”。Codex 与 Kimi Code 已分别通过本机账号完成会话续接测试。WorkBuddy 的本机 MCP 连接测试已实际调用通过；反向 Open API 仍缺真实 OAuth 授权。企业微信机器人收发、应用通知、成员目录和回流通过模拟联调，**尚未用真实企业凭据完成端到端验证**。机器人主动发送受会话和可见范围限制，不能读取个人全部聊天记录。空间资料和成员映射仍保存在当前 Mac；企微参与者只能通过机器人操作获授权的空间，尚不能登录其他设备查看共作。普通邮箱待邀请成员仍不会收到邀请或开通访问。浏览器 Demo 仅作界面预览。

企微摘要规则的配置与本地回调测试已完成，但**大圆能否把摘要投递给另一个机器人尚未确认**；启用规则前还需要实际验证来源 UserID，以及 WorkBuddy 的 OAuth 发送和读取权限。规则只生成分析建议，不会自动修改现有任务。

## WorkBuddy HTTPS 本地助理接入（2026-10-15）

本期新增安全的授权中转服务及桌面接入；不需要把 WorkBuddy 应用 Client Secret 发给员工，也不使用未过审的 HTTP 本机回调。**目前只验证了本地 Mock 上游与真实 Node HTTP 服务之间的流程，尚未部署真实 HTTPS 域名或完成平台授权。** 不等于开放平台应用已经审核通过。

### 部署服务

- 运行环境：Node.js 22.12 或更高版本，无新增依赖；代码 `server/workbuddy-relay.cjs`。
- 按 `server/.env.example` 配置服务进程环境：公开 HTTPS origin、已审核的 Client ID/Secret、32 随机字节的 base64 加密密钥、持久化数据文件的绝对路径。不要将真实值提交到 Git；本项目不会把它们打进桌面安装包。
- 部署前创建数据文件的私有父目录；必须可持久化、仅本服务进程可写。加密密钥、公开地址、Client ID 与密文数据绑定，修改任意一项不能直接沿用旧文件。备份密钥与密文；缺少密钥无法恢复。
- 启动：注入环境变量后 `npm run workbuddy:relay`；或 Node 22.12+ 使用 `node --env-file=/私有目录/relay.env server/workbuddy-relay.cjs`。`.env.example` 是配置样例，不会自动加载。默认仅监听 `127.0.0.1:8787`，前置可信反向代理终止 HTTPS，使用有效证书。不要把服务的明文端口公开。
- 在平台登记 `GONGZUO_RELAY_PUBLIC_URL` 加 `/oauth/callback`，必须与请求逐字一致。最小权限：`user.profile.readable`、`user.localassistant.readable`、`user.localassistant.invokable`。申请已启用的正式应用；登记 HTTPS 不会保证过审。
- HTTP 反向代理保留原路径，不额外添加路径前缀，回调 query 只用于处理，不记录在代理 access log。Token、Secret、Cookie、Authorization 也不能进入代理日志。后台进程日志只输出安全配置错误。
- `GET /healthz` 仅检查中转配置是否就绪；不表示平台应用、账号授权或 PC 已在线。此实现的加密文件存储仅支持**单进程**，不要以同一文件多副本启动，也不要把服务当成无状态多实例部署。

### 在共作里使用

1. 设置 → Agent → WorkBuddy，选「HTTPS 本地助理接口」，填写已部署授权服务的 HTTPS 域名并保存。
2. 点击「用 WorkBuddy 账号授权」。官方浏览器回调由服务端处理；state + PKCE 和桌面的一次性领取校验绑定授权。共作只加密保存不透明中转会话，不接收平台 Access/Refresh Token。
3. 界面自动显示连接状态，离线时提示打开客户端并重连，再在工作里发出任务。仅发送 TaskRunner 已准备的工作上下文和适用记忆；超过 4000 字拒绝发送而不是静默截断。
4. 回复保留「获取最新回复」「我已核对，结束监听」。本地助理接口只有消息记录，**没有文档明确的完成信号**；首条文本不等于执行完成。工具审批和复杂追问先在 WorkBuddy 本身完成；本期不转发 `permission_response`，不伪造审批。
5. 去 WorkBuddy 核对任务结束后，再结束共作监听（带原生确认）。这个动作只释放消息流归属，不停止 WorkBuddy 的任务，也不将任务自动标成已完成。监听期间禁止重新授权、退出或更换服务地址，以免失去原监听归属。

### 已验证与限制

- 令牌服务端 AES-256-GCM 加密，opaque session 索引用 SHA256；短期授权一次性领取、防串用户、失效/取消、安全错误、刷新单飞及重启保留占用状态都有测试。
- 同一 WorkBuddy 账号一次只监听一项工作；外部出现其它用户消息时立即拒绝关联。发送超时不自动重发；响应丢失保留本次稳定 requestId，后续由服务端映射平台消息 ID，完成释放的回包丢失可幂等重试，不会释放其它活跃任务。临时 state/PKCE attempt 在重启后需重新授权。
- 取消标识从授权操作开始捕获，凭据写入后复核取消状态；设置与授权变更有互斥边界。执行配置带 epoch，若任务准备资料期间授权或设置改变，发出前拒绝使用旧配置。不会把不同中转地址的凭据混用，也不会将 relay 会话发到 WorkBuddy 云端接口。
- 不透明会话有效期 30 天；到期须重新授权，WorkBuddy 平台 Token 在服务端按实际有效期续期。若原监听所有者凭据到期或被绕过桌面撤销，锁保持拒绝第二工作，需维护者核对原任务后恢复；不要清空数据文件“解锁”。
- 云端任务不是本期新授权的权限；中转会话不会被发到官方云端接口。原本机 MCP 领取任务仍保留；旧本机 OAuth 模块仅留作开发测试，不再作为桌面的默认授权方式。
- 文件卡片/真正完成的产物通过哪个通道返回，取决于 WorkBuddy 接口；本期没有声称本地助理的附件可直接下载为所有办公格式。现有 CodeBuddy 云端文件回传是另外一条通道。
- 测试：`npm run test:workbuddy-relay`（服务安全测试 + 桌面联调），并运行 `npm test` 全量回归。部署验证必须用真实 HTTPS 回调及已过审 Client ID/Secret；当前缺少这些前置条件，不能标记为已上线。

## 安装本地预览版

下载 `共作预览版-0.1.0-arm64.dmg`，打开后将「共作预览版.app」拖入「应用程序」，之后像普通 Mac 应用一样打开。适用于 Apple Silicon Mac（M 系列芯片）；运行时不需要安装 Node，也不需要终端。Electron 是内部运行引擎，不是用户需要单独启动的程序。

预览版使用独立应用 ID 和独立链接协议 `gongzuo-preview://`，不覆盖也不会唤起旧「共作.app」，沿用开发版数据目录 `~/Library/Application Support/gongzuo-agent-dev`。它与源码开发版共享此目录，因此两者不要同时运行。构建不包含用户数据或密钥。尚未完成 Apple Developer ID 签名与公证，首次打开可能提示开发者无法验证；只在确认来源可信后通过系统的「隐私与安全性」允许打开，不建议关闭系统安全检查。

构建预览包：`npm run dist:preview:mac`（输出到工作区 `outputs/`）。开发版与预览版的密钥保存在各自的钥匙串项中，互相读不到；换用预览版后需在设置里重新填写模型 Key 等密钥，读不到的旧密钥按「未配置」处理，不影响启动。

WorkBuddy 的本机连接、云端任务和本地助理三种选项都包含在预览版里。云端与本地助理接口仍须有效的开放平台 OAuth 授权，安装应用不代表已获授权。云端托管连接器的实际可用范围须在授权后联调确认。

## 从源码本地运行

开发需要 Node.js 22.12 或更高版本。

```bash
npm install
npm start
```

运行检查：

```bash
npm run check
npm test
```

生成 macOS 应用和 ZIP 安装包：

```bash
npm run pack:mac
npm run dist:mac
```

需要 DMG 时可以运行 `npm run dist:dmg`。构建产物位于 `release/`。本地构建默认未签名，正式分发前需要 Apple Developer ID 签名和公证。

## API Key

仓库不保存 API Key，`.env` 和 `.env.local` 已被 Git 忽略，构建产物也不会包含它们。个人配置的 Key 保存在 Mac 的用户数据目录中，并按模型提供方隔离。

模型和外部 Agent 请求由 Electron 主进程发起，遵循两个边界：

1. Key 只由 Electron 主进程或企业服务端读取，渲染进程无法读取。
2. 面向员工分发时由企业服务端持有模型凭据；个人在 Mac 上配置的凭据使用 Electron `safeStorage` 和 macOS 钥匙串支持的加密能力，密文保存在用户数据目录，不写入项目文件。未签名的本地构建可能弹出钥匙串访问提示。
