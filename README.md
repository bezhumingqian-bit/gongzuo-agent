# 共作

面向企业团队的桌面 Agent。员工用一句话发起工作，Agent 结合当前团队空间中的任务、知识和授权信息继续执行；过程、决定和成果留在团队里。团队成员也可以把高频工作发布成内部小应用，供同事长期使用。

当前仓库包含一个可运行的 **macOS MVP**。它具备桌面窗口、本地数据持久化和受限的主进程接口。企业微信智能机器人通过 WebSocket 长连接接收消息，也可向企微允许的会话发送工作消息；需要同步可见成员目录时可另外配置自建应用。飞书、普通微信和邮件尚未接入。

## 已实现

- macOS 原生窗口与菜单，界面采用 Agent 对话作为主操作区
- 工作主页可切换模块工作台、简洁概览与原 Agent 输入界面；模块可显示、隐藏、排序，布局保存在当前设备
- 精简导航：新工作、我的工作、工作空间、团队小应用；选择小应用后直接在右侧主区域使用，构建任务的成果仍在对话右侧预览
- 新建工作、追加消息，并在团队、项目和公共空间之间切换
- 工作对话支持输入 @ 或点击“@ 同事”选择当前空间成员；消息保留提及对象和送达状态
- 工作中的单条文字可手动发送给指定企微 UserID；@ 已关联的团队或项目成员时，会向对应 UserID 定向发送提醒并记录每人的结果；任务信息里可指派负责人并通知企微。已连接机器人时优先通过长连接发送，自建应用可作为备用发送方式
- 企微机器人支持“新建 空间名：目标”“更新 工作ID：进展”“查看 工作ID”，按 UserID 校验空间权限、排除重复事件，并将 Agent 回复私聊发给发起者
- 设置中的“工作规则”可按企微发送者、消息前缀和目标空间筛选摘要，交给 WorkBuddy 或内置 Agent 形成待确认的工作；规则默认关闭。窗口右上角“消息收件”可直接查看企微机器人单聊正文，本机最多保留最近 50 条。在工作中明确询问企微来信内容时，最近至多 10 条会临时提供给当前 Agent 回答，不必先逐条引用；需要把特定来信长期放入工作时再选“作为工作材料引用”。旧版本只保存了时间和发送者，无法恢复正文
- 企微通讯录同步只保存应用可见成员的 UserID 与显示名；可将其关联到团队或项目空间，赋予机器人只读或协作权限并撤销
- “最近参与”按空间收拢工作并默认只展开最近范围，单项工作内可以继续对话
- 从“工作空间 → 新建项目”创建项目空间、关联团队、查看项目工作；创建者可添加待邀请成员，并在“只读 / 协作”之间调整其预设权限
- 工作空间右侧展示该空间的实际资料；可上传文档、按分类和标签整理、搜索、打开、移出及恢复
- 发起工作或继续对话时可主动引用当前空间最多 3 份 PDF、Word 或文本资料；只提取文字，每份最多发送前 12000 字。扫描版 PDF 暂无 OCR，表格和演示文稿尚不能作为 Agent 正文引用
- 输入框旁可将文件上传到当前空间资料，并直接切换新工作的空间；通知、成员和任务更多操作有明确入口
- 对话输入框将执行 Agent 与“工具与技能”分开；Codex 和 Kimi Code 可通过本机已登录 CLI 续接同一工作的文本会话；CodeBuddy 可尝试返回文本；WorkBuddy 默认走本机连接：工作排队，WorkBuddy 通过「gongzuo」MCP 连接器领取、处理并写回（见[连接与测试范围](docs/CONNECTIONS.md#workbuddy-本机连接默认)），开放平台 OAuth 为可选通道；技能示例与企业系统 MCP 尚未接通
- 侧栏搜索可查找本机工作、空间资料和演示应用；团队应用预览可切换页面并录入临时演示反馈
- 工作数据保存到 macOS 用户数据目录，重启后继续使用
- 个人记忆与团队记忆分别保存；可从任务提炼草稿、确认保存、分类打标签并移出记忆
- 设置分为“模型”“Agent”“连接器”三个独立页面；企微首选只填机器人 BotID 和 Secret，自建应用与成员目录收在连接器的高级接入中；保存后可分别检查连接与凭据
- OpenAI、Kimi 和 DeepSeek 模型均可打开各自开放平台，保存独立的模型 ID 与 API Key 后由内置 Agent 调用；网页或客户端登录不会自动授权 API 调用
- 配置模型、Codex、Kimi Code、CodeBuddy、WorkBuddy 或自定义 Agent 后，Mac 版在新建工作与继续对话时会发起请求，并把响应或安全的错误信息留在工作中；工作会先落盘，Agent 在后台按消息顺序处理，失败或中断可重试；每项工作可单独切换执行 Agent；WorkBuddy 需要有效的 OAuth 访问令牌，自定义 Agent 需实现[共作桥接协议](docs/CONNECTIONS.md)
- 输入框的“交给 Agent”和“发企微”是两条独立路径：直接发企微时先确认收件人，只记录并投递该条文字，不调用 Agent；已有工作消息上的“转发到企微”只做转发，原消息若已交给 Agent，其回复仍会保留
- 模型密钥、外部 Agent 令牌、企业微信应用和机器人密钥由 macOS 安全存储加密后保存；界面只能看到是否已配置
- 团队应用的预览、发布演示和再次改进入口
- 渠道消息的基础策略：归档、低风险自动更新、高影响变更待确认
- Electron 安全边界：上下文隔离、渲染进程无 Node 权限、窄 IPC 接口、禁止任意导航
- Agent 服务抽象；没有模型凭据时使用本地模式

“配置已保存”不等于“连接已验证”。Codex 与 Kimi Code 已分别通过本机账号完成会话续接测试。WorkBuddy 的本机 MCP 连接测试已实际调用通过；反向 Open API 仍缺真实 OAuth 授权。企业微信机器人收发、应用通知、成员目录和回流通过模拟联调，**尚未用真实企业凭据完成端到端验证**。机器人主动发送受会话和可见范围限制，不能读取个人全部聊天记录。空间资料和成员映射仍保存在当前 Mac；企微参与者只能通过机器人操作获授权的空间，尚不能登录其他设备查看共作。普通邮箱待邀请成员仍不会收到邀请或开通访问。浏览器 Demo 仅作界面预览。

企微摘要规则的配置与本地回调测试已完成，但**大圆能否把摘要投递给另一个机器人尚未确认**；启用规则前还需要实际验证来源 UserID，以及 WorkBuddy 的 OAuth 发送和读取权限。规则只生成分析建议，不会自动修改现有任务。

## 本地运行

要求 Node.js 22.12 或更高版本。

```bash
npm install
npm start
```

运行检查：

```bash
npm run check
npm test
```

生成 macOS 应用和 ZIP 安装包：

```bash
npm run pack:mac
npm run dist:mac
```

需要 DMG 时可以运行 `npm run dist:dmg`。构建产物位于 `release/`。本地构建默认未签名，正式分发前需要 Apple Developer ID 签名和公证。

## API Key

仓库不保存 API Key，`.env` 和 `.env.local` 已被 Git 忽略，构建产物也不会包含它们。个人配置的 Key 保存在 Mac 的用户数据目录中，并按模型提供方隔离。

模型和外部 Agent 请求由 Electron 主进程发起，遵循两个边界：

1. Key 只由 Electron 主进程或企业服务端读取，渲染进程无法读取。
2. 面向员工分发时由企业服务端持有模型凭据；个人在 Mac 上配置的凭据使用 Electron `safeStorage` 和 macOS 钥匙串支持的加密能力，密文保存在用户数据目录，不写入项目文件。未签名的本地构建可能弹出钥匙串访问提示。
