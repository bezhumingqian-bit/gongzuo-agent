# 对话中的外部能力

员工始终从同一项工作发起、追踪和审阅结果。团队 Agent 是任务的协调者；Codex、WorkBuddy 或企业自己的 Agent 可以成为任务执行者，企业系统提供的 MCP 工具则为执行者提供受控操作。二者都不单独占用主导航。

## 对话交互

输入框旁分成两个轻量入口：“团队 Agent”显示当前执行者，并单独列出可委派的 Agent；“工具与技能”在弹层内分为“技能”和“MCP”两页。技能是团队可复用的做事方法，MCP 是连接企业系统的工具。尚未接入的项目标为“未接入”，技能样例标为“示例”，可查看用途与接入条件，不提供虚假的执行按钮。后续接入后，员工可以在发送前选择执行者和工具。任务中应出现一张交接卡，列出目标、共享资料、允许的操作和审批节点；外部进展与成果回到同一条工作时间线。

默认由系统建议合适的执行者，员工可手动修改。接入了某个 Agent 不等于授权它读取整个空间；每次委派只发送当前任务需要、当前成员有权访问的内容。工具读取和工具写入分别授权，跨系统修改、对外发送、应用发布等动作继续由人确认。

## 接入边界

| 类型 | 接入契约 | 返回内容 |
| --- | --- | --- |
| 外部 Agent | 能力声明、任务委派、状态回调或轮询、取消、结果与错误 | 执行状态、成果、变更、检查记录 |
| MCP 服务 | 工具发现、身份与空间权限映射、逐工具授权、输入输出审计 | 工具结果、来源、实际执行的动作 |

工作应保存外部调用 ID、发起人、空间、授权范围、开始与结束时间、状态和撤销/取消结果。企业身份和凭据由主进程或服务端保管，不能通过渲染进程、任务正文或导出的成果传给外部系统。外部返回内容按不可信输入处理，不能自动扩展权限或继续调用高风险工具。

Codex 和 Kimi Code 已通过本机 CLI 接入，每项工作可续接文本会话，两轮真实短句测试通过；目前不执行仓库修改或工具调用。WorkBuddy 已验证从其客户端调用共作本机 MCP 的连接测试；反向已实现官方本地助理发送与读取接口，但还没有开放平台 OAuth 凭据，因此只通过模拟响应测试。设置页支持临时填入短期访问令牌进行开发联调；正式接入需要受控服务端处理授权和刷新。下一阶段仍需验证真实消息收发、并发会话关联和任务级授权，再扩展到更多 Agent 与 MCP 服务。
