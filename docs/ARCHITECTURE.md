# macOS MVP 架构

本页记录当前桌面端实现。后续的模块清单、对话定制、数据来源适配器和仓储边界见[模块化平台设计](MODULAR_PLATFORM.md)。

## 进程边界

```text
┌──────────────── 渲染进程 ────────────────┐
│ 对话、我的工作、工作空间、团队小应用       │
│ 无 Node.js 权限，不读取文件和环境变量       │
└──────────────────┬───────────────────────┘
                   │ 受限 IPC
┌──────────────────▼───────────────────────┐
│ Electron 主进程                           │
│ 输入校验、任务服务、本地存储、渠道事件策略   │
└──────────────┬───────────────┬───────────┘
               │               │
        workspace.json   后续：模型与企业连接器
```

`preload.cjs` 只暴露明确列出的业务方法。渲染进程不能访问 `ipcRenderer`、文件系统、环境变量或 Node.js 模块。主进程校验调用来源和参数，并负责所有持久化。

## 现有模块

| 文件 | 职责 |
| --- | --- |
| `electron/main.cjs` | 窗口、菜单、IPC、安全策略与应用生命周期 |
| `electron/preload.cjs` | 提供窄而明确的渲染进程接口 |
| `electron/store.cjs` | 原子写入 JSON，并串行处理并发更新 |
| `electron/agent-service.cjs` | 本地 Agent 与渠道消息判断策略 |
| `electron/memory-service.cjs` | 记忆草稿、范围校验与任务上下文筛选 |
| `electron/settings-service.cjs` | 模型与 Agent 配置校验、凭据加密和脱敏读取 |
| `electron/document-service.cjs` | 按空间保存文档、管理分类标签和可恢复的移出状态 |
| `electron/workspace-service.cjs` | 创建项目空间、校验创建者权限与维护待邀请成员名单 |
| `electron/seed.cjs` | 首次启动的示例团队数据 |
| `demo/` | 桌面端界面；浏览器中也可以作为交互 Demo 运行 |

## 数据位置

开发和打包后的应用都把业务数据写入 Electron 的 `userData` 目录，而不是源码目录。JSON 文件使用临时文件加重命名的方式原子更新，并设置为仅当前用户可读写。

长期记忆从任务数据中抽离，分别保存在 `personal-memory.json` 与 `team-memory.json`。每条记忆包含标题、内容、分类、标签、来源任务、确认人、所属范围和状态。任务中的“提炼记忆”只生成可编辑草稿；员工确认后才写入记忆文件。修改记忆会保留旧版内容，移出记忆会归档该条记录，让它不再进入新工作的上下文筛选。

当前应用没有企业身份认证或同步服务，团队记忆只是按工作空间隔离的本机数据。团队正式共享时，需要把团队记忆迁到服务端，以成员身份、空间权限和审计记录控制读写；个人记忆则绑定成员账号并保持独立。

空间资料也按工作空间 ID 隔离。用户选择文档后，主进程验证文件格式和大小，将副本保存在 `userData/documents/`，并在 `documents.json` 中记录名称、大小、分类、标签和状态。读取列表时不向渲染进程暴露文件路径；打开文档由主进程调用系统默认应用。移出只改变状态，保留文件以供恢复。当前文档管理是本机能力，没有组织账号、成员权限或同步，也没有把正文交给 Agent。

## 模型接入

`AgentService` 是模型接入点。设置页可保存 OpenAI API、兼容接口和本机模型服务的地址与模型 ID，也可保存内置或外部 Agent 的选择。配置保存在 `settings.json`，用户输入的凭据经受限 IPC 交给主进程，再通过 Electron `safeStorage` 加密后写入 `credentials.json`；后续读取设置的接口只返回是否已配置的布尔值，不回传凭据。远程接口地址要求 HTTPS，本机回环地址可使用 HTTP。当前尚无 provider adapter 或外部 Agent 协议调用，保存配置不会使模型“已连接”。后续由主进程或企业服务端执行请求。生产环境优先使用企业服务端代理，使员工设备不持有供应商 Key。

创建任务时，主进程只筛选当前成员的个人记忆和任务所属空间的团队记忆，并把结果交给 Agent 服务。个人记忆不会写入团队任务记录。当前本地模式尚无模型调用，因此这一步只完成范围选择，不会生成基于记忆的回答。

模型输出不能直接改动高影响字段。任务负责人、截止时间、权限、预算、对外发送和应用发布都形成待确认操作。聊天中明确的低风险完成状态可以自动更新，但必须保留来源和撤销记录。

## 渠道接入

飞书、企业微信和邮件事件在服务端完成验签、解密、去重和身份映射，再进入统一事件结构。桌面端只订阅当前用户有权访问的任务事件。首版的判断策略已用本地函数固定下来，便于未来替换模型时保持同一审批边界。
